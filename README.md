# UniItalia

**Твоё будущее начинается в Италии.** Русскоязычное приложение для поступления в университеты Италии:
каталог вузов и программ, поиск с фильтрами, стипендии DSU, избранное, аккаунт и админ-панель.

Это **Этап 1 (MVP)** из технического задания. Что сделано, что проверено и что ещё не работает — ниже, без преувеличений.

---

## Что внутри

```
apps/mobile/        Мобильное приложение: Expo SDK 58 + React Native + TypeScript + Expo Router
  src/app/          Экраны (каждый файл — экран, _layout.tsx — навигация)
  src/components/   UI-кит: UniversityCard, ProgramCard, ScholarshipCard, FilterChip, EmptyState,
                    DeadlineBadge, ScreenHeader, VerificationBadge и др.
  src/lib/          Данные (каталог, авторизация, избранное, фильтры), клиент Supabase
  src/i18n/         Все тексты интерфейса (ru.ts) — сюда добавляются новые языки
  e2e/smoke.mjs     Автотест реальных сценариев в браузере (Playwright)
apps/admin/         Админ-панель: Next.js 16 + TypeScript
packages/shared/    Общие типы, справочники (города, регионы, направления, термины DSU),
                    логика поиска/фильтров, демонстрационные данные + тесты
supabase/
  migrations/       SQL: таблицы, индексы, ограничения, триггеры, журнал, RLS, хранилище документов
  seed.sql          Демонстрационные данные (генерируется: npm run seed:sql)
  tests/            Проверки RLS на локальном PostgreSQL
scripts/            Генератор seed.sql, скрипт проверки БД
docs/               Архитектура, источники данных, статус сервисов, план развития
```

Почему **Expo Router**: файловая маршрутизация, встроенные глубокие ссылки
(`uniitalia://university/unibo`, `uniitalia://program/polimi-cse`), одна кодовая база для iOS, Android и веба.

### Честно о данных

* Названия вузов, города, регионы, тип (гос./частный) и официальные сайты — реальные, но **из этой среды разработки
  официальные сайты недоступны**, поэтому все записи помечены `is_demo = true` и «Не проверено».
* Стоимость, требования, экзамены, дедлайны и размеры стипендий **не заполнены намеренно** — в приложении стоит
  «Информация уточняется». Ничего не выдумано.
* Программы — 25 известных англоязычных и итальяноязычных программ; длительность и ECTS — по стандартам
  итальянской системы (3 года/180, 2 года/120, 5 лет/300, 6 лет/360). Перед публикацией каждую нужно сверить.
* Фото вузов не используются (нет подтверждённых прав) — вместо них цветные плашки с инициалами.

## Инструкция для запуска (без опыта программирования)

> Подробная версия со всеми ссылками: [docs/setup-guide.md](docs/setup-guide.md).

### 1. Какие аккаунты нужны

| Сервис | Зачем | Бесплатно |
|---|---|---|
| [GitHub](https://github.com) | хранить код | да |
| [Supabase](https://supabase.com) | база данных, вход пользователей | да (Free: 2 проекта, 500 МБ БД; неактивный проект ставится на паузу через неделю) |
| [Expo](https://expo.dev) | сборки для iPhone/Android | да (ограниченное число облачных сборок в месяц) |
| [Vercel](https://vercel.com) | разместить админ-панель | да (Hobby) |
| Apple Developer | публикация в App Store | **99 $ в год** |
| Google Play Console | публикация в Google Play | **25 $ один раз** |

Лимиты бесплатных тарифов меняются — сверяйтесь с сайтами сервисов.

### 2. Открыть и запустить проект

Нужны [Node.js 20+](https://nodejs.org) и Git.

```bash
git clone <адрес вашего репозитория>
cd Work
npm install
npm run mobile          # запустит Expo; приложение работает на встроенных демо-данных
```

В терминале появится QR-код. Установите на iPhone **Expo Go** из App Store и отсканируйте код камерой
(телефон и компьютер — в одной сети Wi-Fi). Все модули проекта входят в Expo Go, поэтому отдельная сборка не нужна.
Для просмотра в браузере нажмите `w`.

### 3. Создать Supabase и применить миграции

1. На supabase.com → **New project**. Запомните пароль базы.
2. Откройте **SQL Editor** и по очереди выполните содержимое файлов из `supabase/migrations/` (по порядку имён),
   затем `supabase/seed.sql`.
   Либо, если установлен [Supabase CLI](https://supabase.com/docs/guides/cli): `supabase link` и `supabase db push`.
3. **Authentication → Providers → Email**: включено. Оставьте «Confirm email» включённым.
4. **Authentication → URL Configuration**: укажите адрес админ-панели (после шага 6) в Site URL.

### 4. Переменные окружения (без публикации секретов)

Supabase → **Project Settings → API**. Нужны только `Project URL` и `anon public` key
(он публичный, данные защищает RLS). **`service_role` key никуда в проект не кладите.**

```bash
cp apps/mobile/.env.example apps/mobile/.env           # EXPO_PUBLIC_SUPABASE_URL, EXPO_PUBLIC_SUPABASE_ANON_KEY
cp apps/admin/.env.example  apps/admin/.env.local      # NEXT_PUBLIC_SUPABASE_URL, NEXT_PUBLIC_SUPABASE_ANON_KEY
```

Файлы `.env` и `.env.local` уже в `.gitignore` и не попадут в GitHub. Не отправляйте ключи в чат.

### 5. Назначить себя администратором

1. Зарегистрируйтесь в приложении (вкладка «Профиль») или в Supabase → Authentication → Add user.
2. В SQL Editor выполните (подставьте свой email):

```sql
insert into public.admin_users (user_id, role)
select id, 'admin' from auth.users where email = 'you@example.com';
```

Обычная регистрация роль не даёт — это проверено тестами RLS.

### 6. Админ-панель

```bash
npm run admin            # http://localhost:3001
```

Войдите email/паролем администратора → «Университеты» → «+ Добавить».
Для публикации укажите источник (официальная страница), дату проверки и учебный год.
Размещение: Vercel → New Project → импорт репозитория → Root Directory `apps/admin` → добавьте те же две переменные.

### 7. Когда нужна development build вместо Expo Go

Когда добавятся модули, которых нет в Expo Go (например, некоторые карты, push-уведомления на iOS,
вход через Apple), понадобится своя сборка: `npx eas-cli@latest build --profile development`.

### 8. Тестовая сборка и публикация

```bash
cd apps/mobile
npx eas-cli@latest login
npx eas-cli@latest build:configure
npx eas-cli@latest build --platform ios       # или android
npx eas-cli@latest submit --platform ios      # отправка в App Store Connect / TestFlight
```

Для App Store нужен Apple Developer, для Google Play — Play Console, иконки 1024×1024, скриншоты,
политика конфиденциальности (URL), описание на русском.

### 9. Проверить перед релизом

- права на все изображения и логотипы вузов;
- политика конфиденциальности и согласие на обработку данных (GDPR);
- удаление аккаунта из приложения (обязательно для App Store) — уже есть;
- RLS включён на всех таблицах (`npm run test:db`);
- каждая опубликованная запись имеет источник, учебный год и дату проверки; демо-записи сняты с публикации;
- ключ `service_role` не попал в код и в GitHub.

## Команды для разработчика

```bash
npm test -w @uniitalia/shared        # юнит-тесты поиска, фильтров и данных
npm run typecheck                    # TypeScript во всех пакетах
npm run test:db                      # миграции + seed + RLS на временном PostgreSQL (нужен PostgreSQL 15+)
npm run seed:sql                     # пересобрать supabase/seed.sql из packages/shared/data
cd apps/mobile && npm run export:web && NODE_PATH=$(npm root -g) node e2e/smoke.mjs   # e2e (нужен Playwright)
npm run build -w admin               # сборка админ-панели
```
